# This is to allow providing extra defines like WS_MY_BOARD_NAME for any boards using generic module board definitions.
# Instead of the MY_BOARD_NAME suffix, it should match the unique Board ID in ws_boards.h, but
# uppercase with underscores for dashes. e.g. "dfrobot-beetle-esp32c3" becomes WS_DFROBOT_BEETLE_ESP32C3 with -D for define.
# 
# See if the board.txt already has extra board.defines= in any menu entries, or only the basic empty board.defines= 
# so for example this existing one dfrobot_romeo_esp32s3.menu.PSRAM.enabled.build.defines=-DBOARD_HAS_PSRAM
# then you would add a replacement entry with the existing plus additionally the new -DWS_UNIQUE_BOARD_NAME define:
# dfrobot_romeo_esp32s3.menu.PSRAM.enabled.build.defines=-DBOARD_HAS_PSRAM -DWS_DFROBOT_UNIQUE_BOARD_ID
#
# Do the same for the board entry in the platformio.ini file:    build_flags = -DWS_YOUR_UNIQUE_BOARD_ID
#
# This root file is the fallback for every CI target. For a single build target, put the override in
# examples/Wippersnapper_demo/.<ci-platform-name>.boards.local.txt instead: ci-arduino installs the most
# specific file it finds for each example (<example>/.<platform>.boards.local.txt > <example>/boards.local.txt
# > this file) and removes it again afterwards, so per-target files cannot leak into other builds.
#
# Example (lives in examples/Wippersnapper_demo/.lilygo_t_dongle_c5.boards.local.txt):
# LilyGO T-Dongle C5 builds with the generic Espressif esp32c5 board, so needs a unique define.
# The PSRAM menu sets build.defines, so the menu key is overridden (keeping -DBOARD_HAS_PSRAM):
# esp32c5.menu.PSRAM.enabled.build.defines=-DBOARD_HAS_PSRAM -DWS_LILYGO_T_DONGLE_C5
